# Биржевая торговля и оптимизация портфеля

## О проекте

Командный проект, посвящённый оптимизации портфеля из криптовалют. Мы хотим разобраться, как распределять капитал между несколькими криптоактивами так, чтобы добиться хорошего соотношения доходности и риска, и проверить, могут ли методы машинного обучения улучшить классические подходы.

Крипторынок выбран потому, что он отличается высокой волатильностью, круглосуточной торговлей и сильной взаимосвязью активов. Это делает задачу оптимизации портфеля особенно интересной и непростой.

## Цель

Построить и сравнить несколько стратегий формирования криптовалютного портфеля: от простых базовых (например, равные веса) до классических методов портфельной теории и моделей на основе машинного обучения.

## Примерный план работы

1. **Изучение теоретической базы.** Портфельная теория Марковица, метрики риска и доходности (коэффициент Шарпа, просадка и др.), обзор подходов к оптимизации и применения ML в этой области.
2. **Сбор рыночных данных.** Выгрузка исторических котировок по набору криптовалют через открытые API бирж, очистка и подготовка данных.
3. **Анализ данных.** Изучение динамики цен, волатильности и корреляций между активами.
4. **Базовые стратегии.** Реализация простых и классических методов распределения весов в портфеле.
5. **Обучение моделей.** Попытка улучшить результаты с помощью моделей машинного обучения.
6. **Тестирование и сравнение.** Проверка стратегий на исторических данных и сравнение по метрикам доходности и риска.
7. **Выводы и оформление результатов.**

План может уточняться по ходу работы.

## Данные

Общие соглашения: время в UTC, дата — начало дневной свечи; столбцы в таблицах «даты × монеты» называются тикерами (`BTC`, `ETH`, …); итоговые таблицы — в Parquet. Код загрузки лежит в `src/data/`, сырые данные — в `data/raw/<источник>/`, итоговые — в `data/processed/`.

Окружение ставится через [uv](https://docs.astral.sh/uv/):

```bash
uv sync
```

### Binance (цены и объёмы)

**Что выгружено.** Дневные OHLCV-свечи спотовых пар к USDT с 2020-01-01 по последний закрытый день (на момент выгрузки — 2026-10-30). Список монет (20 шт., без стейблкоинов) задан в [src/data/binance_coins.py](src/data/binance_coins.py).

**Как обновить.**

```bash
uv run python -m src.data.binance_download
```

```bash
uv run python -m src.data.binance_build
```

Первый скрипт качает свечи через публичный REST `/api/v3/klines` (ключ не нужен, пагинация по 1000 свечей, повторные попытки при сетевых ошибках и 429). Если `api.binance.com` недоступен, автоматически пробуется зеркало `data-api.binance.vision`; есть и полностью независимый режим `--source archive` через ZIP-архивы [data.binance.vision](https://data.binance.vision). Каждая пара пишется в отдельный `data/raw/binance/<SYMBOL>.csv`, при перезапуске догружаются только новые дни (`--full` — перекачать с нуля, `--coins BTC ETH` — только выбранные монеты).

Второй скрипт склеивает переименованные пары, проверяет качество и собирает таблицы в `data/processed/`:

| Файл | Содержимое |
|---|---|
| `prices.parquet` | даты × монеты, цена закрытия в USDT |
| `volumes.parquet` | даты × монеты, объём торгов в USDT (`quote_volume`) |
| `returns.parquet` | даты × монеты, лог-доходности `ln(close_t / close_{t-1})` |
| `binance_ohlcv.parquet` | длинная таблица: `date, coin, symbol, open, high, low, close, volume, quote_volume` |
| `binance_quality.csv` | итоги проверок по каждой монете |

Проверки: число дней совпадает с ожидаемым, нет дублей, `high ≥ max(open, close)`, `low ≤ min(open, close)`, цены положительные, незакрытая свеча текущего дня отброшена. Если найдена ошибка, скрипт завершается с ненулевым кодом.

**Ограничения и особенности.**

- Шесть монет начали торговаться на Binance позже 2020-01-01: SOL (2020-08-11), DOT (2020-08-18), UNI (2020-09-17), AVAX (2020-09-22), NEAR (2020-10-14), FIL (2020-10-15). До этих дат в таблицах стоит `NaN`; общий период для всех 20 монет — с 2020-10-15.
- **POL = MATIC.** В сентябре 2024 Polygon перевёл MATIC в POL (обмен 1:1). Ряд `POL` склеен из `MATICUSDT` (до 2024-09-10) и `POLUSDT` (с 2024-09-13). Дней 2024-09-11 и 2024-09-12 нет — это единственные внутренние пропуски в данных, они оставлены как `NaN`. Ещё две точки стоит учесть при очистке: свеча 2024-09-10 неполная (торги MATIC остановили днём, объём в ~10 раз ниже обычного), а в первый день POL `high = 1.0` — это всплеск на открытии торгов.
- Пропуски нигде не заполняются, доходность через пропуск тоже `NaN`. Как их обрабатывать, решаем на этапе очистки.
- Цены — только Binance, без усреднения по биржам. Для сверки используется агрегированный источник CoinGecko (см. ниже).
- Цены в REST и архиве совпадают точно. Объёмы расходятся в 5 днях за 2020–2021 (до 2,4% у BTC 2021-01-21), это несостыковка внутри самого Binance. Основной источник — REST.
- Крупнейшие дневные движения — это реальные рыночные события, а не ошибки данных: DOGE 2021-01-28 (лог-доходность 1,59, то есть рост в ~4,9 раза за день), обвал 2020-03-12, TRX 2024-12-03.

### CoinGecko (капитализация и сверка цен)

**Что выгружено.** Для тех же 20 монет получены цены в USD, рыночная капитализация в USD и совокупные объёмы торгов за 24 часа в USD. Выгрузка выполнена 2026-10-31 в 22:16–22:17 UTC (2026-11-01 по Москве). Исходные дневные точки: **2025-11-01 — 2026-10-31, 00:00 UTC**. После выравнивания с датами свечей Binance итоговые таблицы покрывают **2025-10-31 — 2026-10-30: 365 дней × 20 монет**.

**Соответствие ID.** Явный список в [src/data/coingecko_coins.py](src/data/coingecko_coins.py) проверен по ID, названию и символу в сохранённом каталоге `/coins/list`. Это не выбор первого результата по тикеру: одинаковые символы встречаются у разных активов. Таблица с Binance-парами, CoinGecko ID, названиями, ссылками и временем получения каталога — [data/processed/coingecko_ids.csv](data/processed/coingecko_ids.csv). Для `POL` используется `polygon-ecosystem-token` (POL, ex-MATIC), а не legacy `matic-network`: весь запрошенный год находится после миграции MATIC → POL.

**Как воспроизвести и обновить.** В локальном `.env` задайте `COINGECKO_DEMO_API_KEY` по шаблону [.env.example](.env.example). Если файл уже настроен, сохраните существующий ключ. Переменная окружения имеет приоритет. `.env` исключён из Git; ключ передаётся только заголовком `x-cg-demo-api-key` на официальный `api.coingecko.com`, не попадает в URL, сохранённые ответы и журналы.

```bash
uv sync --frozen
uv run python -m src.data.coingecko_download
uv run python -m src.data.coingecko_build
```

Загрузчик вызывает `/coins/{id}/market_chart` с `vs_currency=usd`, `days=365`, `interval=daily`, `precision=full`. Между запросами выдерживается минимум 2,5 секунды; сетевые ошибки, 429 и 5xx повторяются до пяти попыток, учитывается `Retry-After`. Ответ каждой монеты сохраняется атомарно в отдельный JSON. Повторный запуск использует свежие файлы текущего дневного окна, поэтому сбой не требует перекачивать весь набор. Каталог ID кэшируется на семь дней. Для принудительного обновления — `--force`; для отдельных монет — например `--coins BTC ETH`. Перед общей сборкой все 20 файлов должны относиться к одному дневному окну. Обновление заменяет текущий снимок последнего года, а не накапливает многолетний архив.

Сборка и сверка работают **без сети и ключа** по сохранённым файлам. Порог флагов настраивается, например:

```bash
uv run python -m src.data.coingecko_build --threshold-pct 2
uv run python -m unittest discover -s tests -v
```

**Результаты.**

- [data/raw/coingecko/](data/raw/coingecko/) — полный каталог и 20 исходных ответов. JSON-конверт содержит `endpoint`, `params`, `fetched_at` и неизменённый ответ API в `data`.
- [market_caps.parquet](data/processed/market_caps.parquet) — капитализация, USD; индекс `date` в UTC, столбцы в том же порядке, что в Binance.
- [coingecko_prices.parquet](data/processed/coingecko_prices.parquet) — агрегированные цены CoinGecko, USD.
- [coingecko_volumes.parquet](data/processed/coingecko_volumes.parquet) — совокупные скользящие объёмы за 24 часа, USD.
- [coingecko_quality.csv](data/processed/coingecko_quality.csv) — 60 проверок: по три ряда на каждую монету, пропуски, некорректные значения и отброшенные точки.
- [coingecko_binance_comparison.parquet](data/processed/coingecko_binance_comparison.parquet) — подробная сверка цен: дата свечи, исходная полночь CoinGecko, обе цены, относительное расхождение и флаг.
- [coingecko_binance_summary.csv](data/processed/coingecko_binance_summary.csv) — число сравнений, медиана, 95-й перцентиль, максимум и число флагов по каждой монете.
- [coingecko_binance_flags.csv](data/processed/coingecko_binance_flags.csv) — все расхождения выше порога, отсортированные по величине.
- [coingecko_report.json](data/processed/coingecko_report.json) — периоды, параметры, итоговые показатели, ограничения и SHA-256 исходных файлов для воспроизводимости.

**Правило времени.** CoinGecko ставит дневную точку на 00:00 UTC; это не свеча с ценой закрытия будущего дня. Например, точка `2026-10-31 00:00 UTC` сравнивается с закрытием свечи Binance, открытой `2026-10-30 00:00 UTC`. Поэтому в обработанных таблицах дата CoinGecko сдвинута на один день назад. Исходные метки сохранены в JSON и подробной сверке. Последняя свежая внутридневная точка отбрасывается, а не округляется до полуночи. По документации дневная точка появляется около 00:10 UTC: до этого времени сборка использует предыдущее дневное окно. Капитализация строки D доступна только после D+1 00:10; при бэктесте нельзя использовать её для доходности самого D или считать доступной ровно в D+1 00:00.

**Проверки и результат сверки.** Во всех 60 рядах есть 365 корректных дневных значений: нет пропусков, неположительных цен/капитализаций или отрицательных объёмов. По каждой метрике каждой монеты отброшена одна внутридневная точка. Повторяющиеся временные метки вызывают ошибку; некорректные значения заменяются на `NaN` с записью в отчёт, пропуски не заполняются.

На общем периоде проведено **7 300 сравнений**. Формула: `100 × (CoinGecko_USD / Binance_USDT − 1)`; флаг ставится при абсолютном значении **строго больше 2%**. Медианное абсолютное расхождение — **0,0755%**, отмечено **225 наблюдений на 70 датах** (3,08% сравнений). Максимум — **24,98% у FIL за 2026-03-07**: CoinGecko около 1,189794 USD, Binance 0,952 USDT. Есть группы крупных расхождений у альткоинов, поэтому отмеченные точки требуют отдельного разбора. Проверка исходных CSV подтвердила, что сравниваемые закрытия Binance перенесены в `prices.parquet` без изменения.

**Ограничения.**

- Demo предоставляет только скользящие последние 365 дней. Этот снимок не экстраполируется назад; многолетняя капитализация Coin Metrics хранится отдельно (см. следующий раздел).
- CoinGecko агрегирует цены разных площадок в USD, Binance даёт цену одной биржи в USDT. Коррекция курса USDT/USD не применялась; различия площадок, валют и времени измерения могут объяснять часть расхождений. Флаг сам по себе не доказывает ошибку конкретного источника. Отмеченные данные сохранены без автоматической замены или удаления.
- `coingecko_volumes.parquet` не эквивалентен Binance `quote_volume`: другой охват площадок и скользящий 24-часовой интервал.
- CoinGecko может пересматривать исторические данные. Сохранённые исходные ответы и хэши фиксируют именно этот снимок; повторная выгрузка может дать другой результат.
- Лимит запросов зависит от тарифа аккаунта. Загрузчик ограничивается примерно 24 запросами в минуту; первый полный запуск потребовал 21 успешный запрос (каталог + 20 монет).

Официальная документация: [аутентификация Demo](https://docs.coingecko.com/demo/reference/authentication), [каталог ID](https://docs.coingecko.com/demo/reference/coins-list), [история и ограничения](https://docs.coingecko.com/demo/reference/coins-id-market-chart).

### Coin Metrics Community (цены и капитализация с 2020 года)

**Что добавлено.** Бесплатная выгрузка из Community API без ключа: `PriceUSD` (цена закрытия в USD) и `CapMrktEstUSD` (капитализация по обращающемуся предложению, USD). Снимок получен 2026-10-31 UTC. Календарь — **2020-01-01 — 2026-10-30, 2 495 дней × 20 монет**. Запрошен 21 исходный актив: для столбца `POL` отдельно получены `matic` и `pol`. Названия проверены по `/reference-data/assets`, доступность обеих дневных метрик — по `/catalog-v2/asset-metrics`.

Для многолетней капитализации используйте **[coinmetrics_market_caps.parquet](data/processed/coinmetrics_market_caps.parquet)**. Файл `market_caps.parquet` относится к годовому снимку CoinGecko; источники не смешиваются и не подменяют пропуски друг друга. Метрика `CapMrktCurUSD` не используется: она основана на другом определении предложения и может учитывать, например, заблокированные монеты.

**Воспроизведение.**

```bash
uv run python -m src.data.coinmetrics_download
uv run python -m src.data.coinmetrics_build
```

Загрузчик запрашивает `frequency=1d` с 2020-01-01 по последний завершённый день UTC. Пример фиксации даты: `--end 2026-10-30`. Пауза между запросами — минимум 6,1 секунды; до пяти попыток при сетевых ошибках, 429 и 5xx, с учётом `Retry-After`. Пагинация идёт по `next_page_url` до конца; все страницы сохраняются без изменения внутри JSON-конверта с параметрами и временем получения. Запись атомарная, по одному файлу на актив. Кэш с теми же параметрами и датой загрузки позволяет продолжить после сбоя. `--force` обновляет снимок, `--coins POL` загружает оба ряда Polygon. Каждый новый снимок запрашивает историю целиком, чтобы учитывать пересмотры источника; старые снимки автоматически не архивируются.

Сборка работает без сети, требует полный комплект файлов с одной конечной датой и сохраняет единый UTC-индекс и порядок 20 столбцов. Повторяющиеся даты, чужие активы, незакрытый день или незавершённая пагинация вызывают ошибку. Нулевые/отрицательные/неконечные цены и капитализации становятся `NaN` и учитываются в проверках; отсутствующие значения не заполняются. Все тесты запускаются командой `uv run python -m unittest discover -s tests -v`.

- [coinmetrics_prices.parquet](data/processed/coinmetrics_prices.parquet), [coinmetrics_market_caps.parquet](data/processed/coinmetrics_market_caps.parquet) — две многолетние таблицы «даты × монеты».
- [coinmetrics_ids.csv](data/processed/coinmetrics_ids.csv), [coinmetrics_coverage.csv](data/processed/coinmetrics_coverage.csv) — соответствия ID, периоды их использования и доступность метрик по каталогу.
- [coinmetrics_sources.parquet](data/processed/coinmetrics_sources.parquet) — выбранный исходный актив для каждой даты и монеты, включая переход MATIC/POL.
- [coinmetrics_quality.csv](data/processed/coinmetrics_quality.csv), [coinmetrics_gaps.csv](data/processed/coinmetrics_gaps.csv) — 40 проверок рядов, флаг `requires_migration_review` для капитализации POL и все интервалы пропусков с разделением на начальные, внутренние и конечные.
- [coinmetrics_polygon_transition.csv](data/processed/coinmetrics_polygon_transition.csv) — оба исходных ряда вокруг миграции, выбранные значения, изменения цены, капитализации и подразумеваемого предложения.
- [coinmetrics_coingecko_comparison.parquet](data/processed/coinmetrics_coingecko_comparison.parquet), [coinmetrics_coingecko_summary.csv](data/processed/coinmetrics_coingecko_summary.csv), [coinmetrics_coingecko_flags.csv](data/processed/coinmetrics_coingecko_flags.csv) — подробная сверка, сводка и отмеченные расхождения.
- [coinmetrics_alignment.csv](data/processed/coinmetrics_alignment.csv) — проверка сдвигов дат −1, 0 и +1 день; диагностический отчёт, без автоматического подбора сдвига по данным.
- [coinmetrics_report.json](data/processed/coinmetrics_report.json) — периоды, показатели, правила, аудит миграции и SHA-256 входных файлов.

**Пропуски.** В ценах 1 436 пустых ячеек, в капитализации — 1 479; все они находятся **до первого доступного значения соответствующей метрики**. Внутренних и конечных пропусков нет, некорректных значений в выбранных рядах не обнаружено. Позднее начало не всегда означает дату появления монеты: метрика может стать доступна позже самой монеты или её листинга на Binance.

- SOL: цены с 2020-04-10, капитализация с 2020-04-11.
- DOT: цены с 2020-08-20, капитализация с 2020-08-23.
- AVAX: обе метрики с 2020-09-23; UNI — с 2020-09-18; FIL — с 2020-10-16.
- NEAR: цены с 2020-10-15, капитализация только с 2020-11-23.
- У остальных 14 монет обе метрики доступны на всём запрошенном календаре. Цены всех 20 монет одновременно доступны с **2020-10-16**, обе метрики — с **2020-11-23**. Это характеристика покрытия, а не гарантия сопоставимости капитализации в момент миграции Polygon.

**Время и сверка.** В Coin Metrics `PriceUSD` с частотой `1d` и меткой D обозначает **закрытие самого дня D**, хотя timestamp имеет вид `D 00:00 UTC`. Поэтому дату Coin Metrics не сдвигаем. Сравниваем её с уже обработанной строкой CoinGecko D, полученной из исходной точки D+1 00:00 UTC. Правило подтверждено документацией и проверкой соседних сдвигов: медиана по медианам 20 монет составляет примерно 0,121% без сдвига и 1,94–1,97% при сдвиге на день. Значения конца дня нельзя использовать для сделок в начале этого же дня; точное время исторической публикации в выгрузке отсутствует.

Общий период с CoinGecko — **2025-10-31 — 2026-10-30**, по **7 300 сравнений на каждую метрику**. Формула: `100 × (CoinMetrics / CoinGecko − 1)`, оба источника в USD. По ценам медианное абсолютное расхождение **0,1079%**, **247** наблюдений превышают 2%; максимум **20,04% у FIL за 2026-03-07**. По капитализации медиана **0,1149%**, **188** наблюдений превышают 5%; максимум **30,42% у UNI за 2026-06-26**. Пороги предназначены для отбора наблюдений на проверку, а не для установления виновного источника; изменить их можно через `--price-threshold-pct` и `--cap-threshold-pct`.

**MATIC → POL: существенный разрыв капитализации.** Правило задано по [миграции Polygon PoS 2024-09-04](https://polygon.technology/blog/matic-to-pol-migration-is-now-live-everything-you-need-to-know): до этой даты берётся `matic`, начиная с неё — `pol`, для обеих метрик. На Binance торги POL начались 2024-09-13, поэтому дата смены ID агрегированного источника отличается от биржевого листинга. Coin Metrics даёт значения и на дни остановки Binance; это другой источник, а не заполнение отсутствующих свечей Binance.

В проверенном окне 2024-08-28 — 2024-09-20 цены MATIC и POL на одной дате отличаются менее чем на 0,75%. Однако 1:1 обмен токенов **не обеспечивает непрерывность их отдельно учитываемой обращающейся капитализации**. На стыке 3 → 4 сентября выбранная капитализация падает примерно с **3,704 млрд до 0,106 млрд USD (−97,14%)**, тогда как цена меняется на **−4,44%**. 6 сентября капитализация выбранного POL возрастает на **1 317%** при изменении цены примерно на −1%. Это разрывы учёта предложения в процессе миграции; такой скачок нельзя трактовать как обычное падение/рост рыночной стоимости объединённого актива.

Значения сохранены и отмечены в аудите. Капитализации MATIC и POL не складываются, не масштабируются и не подменяются друг другом после выбранной границы. **Объединённый столбец POL по капитализации не является непрерывным экономическим индексом.** Для бенчмарка по капитализации через миграцию потребуется отдельное согласованное правило работы с POL либо проверенная реконструкция предложения. Эта неопределённость остаётся явно обозначенной; её не решает простое отсутствие `NaN`.

**Ограничения и атрибуция.** `CapMrktEstUSD` использует историческое сообщаемое обращающееся предложение, а не сегодняшнее предложение, умноженное на старую цену. При этом Coin Metrics может получать сведения о предложении через CoinGecko, поэтому сверка капитализации не полностью независима. История может пересматриваться и не является архивом данных «как они были известны в тот день». Полное покрытие с 2020-01-01 не обещается для монет, появившихся позднее или имевших задержку покрытия.
